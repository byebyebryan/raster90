# Development and checks

Run commands from the repository root unless a platform section says otherwise.
`rtk` is the workstation's CLI wrapper; elsewhere run the underlying command
without it (`rtk proxy` forwards a command without filtering). Python tooling
uses the standard library. Runtime generation is separate from device actions.

## Routine repository checks

```sh
rtk python3 -B tools/check_repository.py
```

This entry point checks documentation links/anchors, repository boundaries,
licensed/public media, generated asset closures, presentations, and focused
Python tests. It does not install dependencies, mutate devices, or regenerate
tracked files. The same portable command runs in CI without RTK.

## Generate assets

Update the authoritative matrices, regenerate the affected outputs, then inspect
the result. Generated runtime files and component previews are tracked on
purpose; edit their sources rather than their generated bytes.

```sh
rtk python3 -B tools/generate_raster90_assets.py
rtk python3 -B tools/render_raster90_font_family.py
rtk python3 -B tools/render_raster90_icon_family.py
rtk python3 -B tools/generate_raster90_zepp_assets.py
```

Each script supports `--check` for byte/closure verification without writing.
The Wear generator owns 215 runtime/preview PNGs, including 128 weather-motion
frames. The Zepp generator owns 119 static PNGs. Component presentations remain
self-contained local previews alongside their source. Counts describe this
tree; the generators enforce their expected surfaces.

Historical study renderers under `tools/render_raster90_*study*.py` and
`design/raster90/` retain comparisons. Some also supply shared layout constants
to the runtime generator; they are not safe to delete based on their names.
Their disposable outputs belong under `outputs/raster90/studies/<study>/`.

## Wear OS build

```sh
JAVA_HOME=/opt/android-studio/jbr rtk proxy ./gradlew \
  :watchfaces:raster90:assembleDebug \
  :watchfaces:raster90:lintDebug
```

Debug output:
`watchfaces/raster90/build/outputs/apk/debug/raster90-debug.apk`.
The bundle stays resource-only with `android:hasCode="false"`; do not add
application logic or a required phone companion. Any future provider/app is a
separate bundle, created only for a concrete requirement.

### WFF schema and memory

Official tools come from [Google's watchface tools](https://github.com/google/watchface).
Keep downloaded binaries/licenses under `outputs/tooling/`; do not commit them.
The locally checked XML validator is 1.7.0. With those binaries installed:

```sh
rtk proxy /opt/android-studio/jbr/bin/java -jar \
  outputs/tooling/google-watchface/wff-validator.jar 2 \
  watchfaces/raster90/src/main/res/raw/watchface.xml
rtk proxy /opt/android-studio/jbr/bin/java -jar \
  outputs/tooling/google-watchface/memory-footprint.jar \
  --watch-face watchfaces/raster90/build/outputs/apk/debug/raster90-debug.apk
```

Both commands were rechecked during the 2026-10-07 documentation pass against
the unchanged runtime. Retain tool version, APK hash, and report with a runtime
checkpoint. Schema/memory checks complement build/lint and do not prove appearance.

Deploy/capture through [Device Setup](device-setup.md). Repeat device validation
when runtime behavior changes, preserving interactive/ambient, 12/24-hour,
truthful weather, and round-edge evidence. Publishing this documentation or
its asset guide does not establish a new watch-face runtime checkpoint.

## Amazfit Balance build

From `watchfaces/raster90-zepp/`:

```sh
rtk npm ci
rtk npm run check
```

`check` runs focused source/manifest tests, verifies the generated closure, and
builds the ZAB with the pinned project-local Zeus CLI. Build output stays under
ignored `dist/`. Use `rtk npm run generate` to regenerate from the canonical
matrices. For an authorized physical preview after those gates:

```sh
rtk npm exec -- zeus preview --target "Amazfit Balance"
```

Zepp login, QR preview, simulator, and physical actions remain distinct from
local checks. See the [package README](../watchfaces/raster90-zepp/README.md)
for bindings/lifecycle and [Validation](validation.md) for the static port's
limitations. The 2026-10-07 registry/audit check still found Zeus 1.9.3 as
latest: zero production advisories, 48 development-tool advisories (3 low,
13 moderate, 30 high, 2 critical). npm's fix proposal downgrades Zeus to 1.6.7.
The CLI dependency tree builds the ZAB and is not packaged on the watch.
Keep the pin; assess compatibility before any separate dependency upgrade or
override. Audits change over time, so recheck rather than treating this count
as a permanent guarantee.
