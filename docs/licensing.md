# Licensing and provenance

The owner selected MIT for code and CC0 1.0 for original artwork on 2026-10-07.

| Material | Terms |
|---|---|
| Project-authored code, build configuration, documentation, and site shell | [MIT](../LICENSE) |
| Original bitmap glyph shapes, icon matrices, weather-animation artwork, palettes, and generated artwork exports | [CC0 1.0 Universal](../LICENSES/CC0-1.0.txt) |
| Retained Pixel Operator TTFs | Their supplied [CC0 notice](../third_party/pixel-operator/LICENSE.txt) and [provenance](../third_party/pixel-operator/README.md) |
| Gradle wrapper and other upstream material/dependencies | Their original licenses/notices; project licensing does not replace them |

For mixed matrix-source Python files, original artwork data is CC0 and the
implementation code is MIT. The same art dedication applies to PNG/GIF and
matrix-data exports generated from those shapes. The complete source families
are project-owned; retained comparison artwork follows the same art policy.
Raster 90's original exploratory concept artwork is included in the dedication.

Runtime captures document the platform as well as Raster 90. The dedication
applies to the Raster 90 artwork within them, not third-party system UI or
platform branding. Keep capture provenance and distinguish those images from
generated artwork exports.

`third_party/` preserves source notices, authorship, and provenance. Pixel
Operator is a design starting point; its TTFs are not packaged at runtime.
Pixelarticons is research only and has not been vendored or traced. Locally
downloaded validation tools stay in ignored `outputs/tooling/` with their
upstream notices. npm/Gradle dependencies retain their own terms.

The project name and platform identities are descriptive references. The CC0
dedication covers original artwork; it does not declare third-party material
to be project-owned.
