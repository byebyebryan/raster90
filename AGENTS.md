# Raster 90 — agent guidance

@/home/bryan/.codex/RTK.md

Raster 90 is a product repository for a resource-only Wear OS watch face and
an independent static Zepp OS port for the original Amazfit Balance. Wear OS is
the design baseline. Read the relevant current docs before changing behavior.

## Product and packaging constraints

- Public name: **Raster 90**; `RASTER/90` is optional visual styling. The model
  name survives the change from the provisional 90×90 raster to 150×150.
- WFF v2; `minSdk=34`, `compileSdk=35`, `targetSdk=35`; application ID
  `io.github.byebyebryan.raster90.watchface`. Keep `android:hasCode="false"`,
  format version 2, and Kotlin disabled. No Java/Kotlin services, legacy
  watch-face renderer, or required phone companion in this bundle. Use the
  lowest WFF version that supports the design; change direction only for an
  explicit requirement.
- Zepp app ID `1125469`, v3 API boundary, native 480×480 Balance target, and
  project-local Zeus dependency remain separate from Gradle. Do not silently
  copy Wear OS features into that adapter.
- Time/date/weather/steps/battery are the fixed information set. No seconds;
  static colon; centered text-only date; icon-led single-line rows. Do not
  restore `WX`, `STP`, `BAT`, or a calendar icon.
- Use one centered 450×450 active frame and fictional 150×150 framebuffer:
  solid 3×3 source cells, no cell gutters, blending, or fractional source-art
  resampling. WFF canvas is 466×466; Zepp canvas is 480×480.
- Compact glyphs are project-owned 5×7 matrices. Primary time uses the selected
  reviewed clean-chamfer cut. Square and legacy fine chamfer remain controls.
  Degree marks are closed; source TTFs stay outside packaged runtime resources.
- Icon storage is 16×16 with a 15×15 drawable field centered on cell `(7,7)`.
  Source row/column 15 remain unlit in every static and moving frame. Tiles
  are 48×48: static unlit cells are transparent, motion frames are opaque black.
  Keep the authored `four-toe-vertical` footprints and selected weather family.
  Pixelarticons is research only, never a dependency or traced source.
- Weather owns the indexed-color plane (at most four visible entries per
  frame). Ordinary text/steps are white. Battery icon alone uses the canonical
  white/yellow/orange/red bands; ambient hides all non-time fields.
- WFF weather motion is eight frames at 4 fps, once on `ON_VISIBLE`, restoring
  `FIRST_FRAME`. Fresh recognized families only. Stale/unavailable/unknown/
  out-of-range/ambient states remain static. The presentation GIF loop is not
  runtime behavior.
- Preserve truthful available/stale/unavailable weather. The unavailable row
  is the neutral icon plus `--`. Wear OS defaults to Celsius with an explicit
  Fahrenheit editor option and real provider-unit conversion. Zepp uses native
  units and has no stale-age or animation contract.
- Wear OS centers complete formatted information rows on whole source cells;
  icon, animation, stale marker, and value move together. Zepp retains fixed
  horizontal anchors. Keep runtime and deterministic preview geometry aligned;
  optical or band changes require an explicit design decision.
- Sunrise/sunset is [deferred](docs/sunrise-sunset-spike.md). Rare color events
  and additional complications are not scheduled work.

## Change and evidence discipline

- Inspect current Git state and relevant source before editing. Keep changes
  reviewable and preserve work made by others.
- Canonical artwork lives in `fonts/raster90/family.py`,
  `icons/raster90/family.py`, and `icons/raster90/animation.py`. Regenerate
  affected runtime/presentation outputs and use `--check`; never hand-edit
  generated bytes or duplicate matrices in a new consumer.
- Historical study modules still supply some shared runtime layout constants.
  Trace imports before moving or removing them.
- Use `tools/check_repository.py` for routine portable checks. Add meaningful
  validation for new behavior; docs-only changes need link/format review,
  not device deployment. Runtime changes also need relevant build/lint,
  WFF XML/memory gates, and target rendering checks.
- Explicitly target every ADB operation. Discover serials dynamically and prove
  physical model/API or exact AVD identity first. `wear5-opw3` is the 466×466
  primary; `wear5` is the unchanged 454×454 reference. The generic Android-15
  backup is not a Wear target. The phone is optional.
- Never run emulator root/appops/test-location or console power commands on a
  physical device. Confirm selection, unobscured WFF window, and power state
  before retaining a capture. Re-prove identity before stopping an emulator.
- Pairing codes and transient endpoints/serials must not be retained. An
  install or debug-surface favorite ID is not visual acceptance.
- Keep synthetic previews, simulated-provider data, physical captures, and
  wearer reports distinct. A still image does not prove animation; historical
  ambient evidence does not prove sustained AOD on the current physical tree.
  Reliable use was reported on both platforms; AOD was unused on both.
- Keep disposable artifacts under ignored `outputs/`: product studies in
  `outputs/raster90/studies/`, device evidence in `outputs/raster90/captures/`,
  external references in `outputs/references/`, validators in
  `outputs/tooling/`. Do not erase retained evidence during routine cleanup.
- Public capture copies belong in `docs/media/` with exact hashes/provenance.
  Copy bytes without retouching. Site publication uses only its curated build
  output, never the entire repository or ignored evidence tree.
- Project code is MIT; original artwork is CC0. Preserve upstream notices.
